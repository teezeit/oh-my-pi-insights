What /insights actually does

Every omp session already wrote a log to disk. This extension reads those logs and turns them into a report about how you work. The whole thing is three transforms, and the numbers below are from your own last run — 295 logs on disk, $4,595.54 of recorded spend.

The whole idea in one line

Raw logs295 .jsonl files
~millions of lines of JSON
→counting
Numbers191 session summaries
cost, tools, errors, timing
→a model reads them
Wordsan HTML report
"here is your friction"

The first arrow is pure arithmetic — no model, no money, nothing to get wrong. The second arrow is the only place a model is involved, and it never sees raw logs: it sees the numbers. That split is the whole design.

What is on disk before you run anything

omp wrote all of this already

One folder per project directory, one .jsonl file per session, and — this is the part people miss — a sidecar folder next to it holding the logs of every subagent you spawned and the advisor. Those sidecars are separate sessions that spent real money.

1

Scan: list the files, fingerprint them

milliseconds · no model

It walks that tree and builds a tiny record per session: where the log is, which sidecars belong to it, and a fingerprint that is just the file's byte size and modification time. The fingerprint is the trick that makes repeat runs cheap — if it is unchanged, the file cannot have changed, so last run's answer is still valid and the file is never opened again.

2

Count: read each log line by line, add things up

the arithmetic half · no model

A session log is one JSON object per line. The parser walks them and accumulates counters. Two examples of what a line looks like and what it contributes:

a line in the log — assistant reply

{ "type":"message",
  "message":{ "role":"assistant",
    "model":"claude-opus-4-8",
    "usage":{ "input":2, "output":815,
      "cacheWrite":85826,
      "cost":{ "total":0.5567975 } } } }
→

what it adds

total_cost      += 0.5567975
output_tokens   += 815
cache_write     += 85826
model_usage["claude-opus-4-8"] += 1

omp writes the actual dollar cost of every call into the log. Nothing is estimated from a price table.

a line in the log — a tool that failed

{ "message":{ "role":"toolResult",
    "toolName":"edit",
    "content":[{"text":"File not found: pr-3755.md…"}],
    "isError":true } }
→

what it adds

tool_errors            += 1
tool_error_categories["file_edit"] += 1

It is a boolean the harness set, not a guess from reading the error text. The category comes from the tool's name.

Same pass also notices: when you interrupted a generation mid-flight, when you escalated thinking level or switched model mid-session, how long you waited for the first token, how long the agent waited for you, which languages the edited files were in, lines added and removed, git commits and pushes, hours of day you were active.

Then the sidecars are read the same way and folded into the parent, but kept labelled, so the report can say where the money went instead of just how much:

4

Facets: ask a cheap model what each session was about

1 call per new session · smol model · costs money

Counters cannot tell you "the user wanted a bug fixed and did not get it". So for each session the transcript is formatted into readable text and handed to the smol model with a fixed question list. The answer must come back as a fixed JSON shape — this is classification, not an essay, which is why it runs on the cheap model.

Sessions over 30k characters get chopped into 25k chunks that are summarised first, then the summaries are classified. 50 sessions per run, max, by default.

5

Aggregate: 191 objects collapse into one page of text

no model

All the metas are summed, all the facets are tallied, and week-over-week differences are computed (with noise gates, so a 2% wobble is not reported as a trend). The result is one plain-text block — this is the only thing the expensive model ever sees. Your transcripts never leave this step.

the shared data block (excerpt, synthetic numbers for illustration)

200 sessions · 2026-01-01 → 2026-02-01 · 30 active days · 3000 user messages
cost $500.00  =  primary $400.00 + advisor $50.00 + subagent $50.00
tokens in 20M · out 20M · cache read 6000M · cache write 200M
tools: bash 10000 · read 4000 · edit 2000 · eval 2000 · hub 1000 · todo 1000 · grep 800
errors 1000 · steering 200 · thinking escalations 600 · model switches 300 · compactions 20
median TTFT 2.0s · median wait for you 100s · 200 parallel-session overlaps
facets: 50 classified - outcomes, friction types, goals, satisfaction
week diff: errors down 25% · 2026-01-15 switch provider/model-a -> provider/model-b, errors down 50%
your setup: installed skills, model roles, config.yml

That last line matters: the model is told which omp features you actually have, otherwise its advice would be invented.

6

Write: eight questions, asked in parallel, then one summary

8 + 1 calls · your active model · costs money

The same data block is pasted into eight different prompts, each asking for one section of the report as JSON. They run concurrently. Then a ninth call reads the data block and the eight answers and writes the top-of-page summary.

PromptQuestion it is really asking
project_areasWhat were the 4–5 things this person was actually working on?
interaction_styleHow do they talk to the agent — long specs, terse nudges, interrupts?
what_worksWhich patterns are paying off and should be kept?
friction_analysisWhere does it keep going wrong, and is that the tool or the prompting?
suggestionsWhat should they change, using only omp features they have?
model_efficiencyHeavy model on trivial work? Weak model on hard work? Quota burn?
on_the_horizonWhat becomes possible as models improve?
fun_endingOne memorable moment from the corpus.
synthesisRead all eight, write the "At a Glance" opener.
💾 Cached under sections/<hash>.json, where the hash is of the data block plus your model id. Same corpus and same model ⇒ identical prose ⇒ re-render is free. Different corpus ⇒ new prose, honestly.

So what does a run actually cost?

SituationModel callsWhy
First run ever, 120 sessions~50 smol + 9 activeEverything uncached. Measured: 8m6s.
Run again 10 minutes later0–9Metas and facets are cached. Sections re-generate only if the corpus moved — and it moves every time you use omp, which is honest, not a bug.
--no-llm0Renders from caches, reuses the newest prose, and says so in the report.
--refresheverythingDeletes facets, ignores section cache. The expensive path, for when you changed the prompts.
The model never sees a raw transcript at the expensive tier. Transcripts go only to the cheap smol model in step 4, one session at a time, and the result is a fixed JSON classification. The active model only ever reads the aggregated statistics block from step 5.

How the model is called at all

omp gives extensions credentials but no completion client. Rather than reimplement a provider client, callModel spawns omp -p with the prompt on stdin — inheriting every provider, auth scheme and rate-limit fallback omp already supports. The subprocess runs with --no-session --no-tools --no-extensions --no-skills --no-title, so it answers and nothing else, writes no log of its own, and therefore never shows up in the next run's corpus.
